## Milestone A1: real voice lifecycle

Implement in order:

1. Define the voice adapter and test its transitions against a fake transport. `start` is single-flight, `stop` is idempotent, subscriptions return an unsubscribe function. Stop during connection prevents a late connection from reopening media.
2. Audit the existing feature implementation before changing dependencies (see below). Prefer the official Deepgram Browser Agent SDK: core `@deepgram/agents` behind the adapter, or React hooks if they preserve a reusable boundary. Use current SDK APIs, not direct translations of OpenAI methods. Start with Deepgram-managed `open_ai` / `gpt-4o-mini` in the Standard tier, subject to current availability/pricing and trial credits; omit a custom `think.endpoint`. Do not require `OPENAI_API_KEY` or a bring-your-own OpenAI endpoint. The server uses `DEEPGRAM_API_KEY` with Member-level permissions or higher to call `POST https://api.deepgram.com/v1/auth/grant`. Retain the existing internal `{ clientSecret, expiresAt }` normalization (ISO UTC expiry); here `clientSecret` contains the temporary Deepgram bearer token, not an OpenAI credential. Keep token handling inside A's adapter and never expose permanent keys, raw provider payloads, or credential logs.
3. Integrate authenticated deployment into the existing `POST /api/realtime/token` handler with body `{ sessionId }`. Its present implementation is local-only; C's helpers are not connected yet. For the deployed flow, call C's `requireUser` and `requireOwnedSession` before issuance; absent auth integration/configuration returns 503, anonymous requests 401, foreign sessions 404. Return `no-store`; validate same-origin POSTs and enforce the agreed per-user request limit. A simple in-process limiter is only a local aid; keep public issuance disabled until deployment-wide abuse controls exist. C coordinates deployment controls; A owns route enforcement.
4. For independent manual development before C lands, use a minimal development-only voice harness, separate from B's `/study`, bound to loopback. A Node-only issuer or strictly local development route may supply the temporary token. Before enabling it, audit guards so production and preview deployments cannot serve the harness or issue billable credentials, even without C's auth. Do not add a deployed auth-bypass flag. Committed harness code must remain development-only; credentials and local artifacts stay untracked. Automated tests inject a fake issuer. The default token TTL is 30 seconds; mint on explicit connect and use immediately, not from a stored permanent browser key.
5. Implement explicit start, microphone permission, listening/speaking indicators, natural speech barge-in, and explicit interruption. Wire current SDK user-speech events to immediate playback interruption so students can continue speaking. Release tracks, playback/audio contexts, SDK/WebSocket connections, timers, and listeners on stop, failure, unmount, and retry. Keep one active connection and bound reconnection behavior so retries cannot reopen a stopped session or repeatedly mint billable credentials.
6. Add concise Socratic mathematics instructions for broad high-school and introductory college conversation: follow the student's topic, use concrete explanations or guiding questions as helpful, allow thinking time, do not roleplay Isaac Newton, and do not claim to see work, verify it with unavailable tools, or remember history before those inputs exist. The distributive-property limit applies to automated work analysis/proactive intervention, not conversational topics; conversation alone is not a verified learning event. Surface denied permission, expired credential, missing configuration, network failure, and disconnect as recoverable errors.

**External requirements:** a Deepgram account with usable trial credits (verify balance/model access), a server-only Member-level-or-higher key, microphone, and a browser supporting the SDK's audio capture/playback and WebSocket connection. Use localhost or HTTPS. No separate OpenAI API key is needed for managed voice. C's auth, owned study session, and abuse controls are required for deployed voice. B is not required for local adapter validation.

**A1 acceptance:** a developer can start a real conversation, capture microphone audio, hear a spoken response, interrupt speech naturally, continue the conversation, stop, and start again. Report local real-voice success separately from deployed integration readiness.

### Preserved A1 technical handoff

- The core SDK connection uses Nova-3 input, managed `gpt-4o-mini`, and Aura-2 Thalia output; verify model availability/credits before live use.
- The actual `VoiceSession` API is `start({ sessionId })`, `stop()`, `interrupt()`, bounded `sendText(message)`, `getState()`, `getSnapshot()`, and `subscribe(listener)`. Subscribers receive a change notification and read the stable state/error snapshot; `deliver` remains an A2 proposal. Shared tutoring types are unchanged.
- `npm run voice:dev` creates an ignored `/dev/voice` route, binds loopback, and sets a random per-run server capability. The handler validates capability, exact same-origin POST, loopback Host, bounded JSON, and a five-attempt/ten-minute process limit. Ordinary dev, production, previews, and CI cannot issue tokens. Do not use public tunnels; use `npm run voice:dev -- --clean` to remove a leftover generated harness after a crash.
- The wrapper waits for settings acknowledgement before microphone startup; handles natural user-speech interruption and playback-drain state; disables automatic reconnect; and releases late microphone permission results, timers, listeners, playback, and connection resources. Explicit interruption silences/drops current playback without claiming server-generation cancellation.
- Preserve existing lifecycle, delayed-permission, playback-drain, SDK-event, credential, request-guard, and harness-script tests. Mocked results do not establish audible playback, natural acoustic interruption, or physical microphone cleanup. Setup and manual acceptance remain in [the voice handoff](../ai-voice.md).
