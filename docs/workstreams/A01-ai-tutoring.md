## Milestone A1: real voice lifecycle

Implement in order:

1. Define the voice adapter and test its transitions against a fake transport. `start` is single-flight, `stop` is idempotent, subscriptions return an unsubscribe function. Stop during connection prevents a late connection from reopening media.
2. Audit the existing feature implementation before changing dependencies (see below). Prefer the official Deepgram Browser Agent SDK: core `@deepgram/agents` behind the adapter, or React hooks if they preserve a reusable boundary. Use current SDK APIs, not direct translations of OpenAI methods. Start with Deepgram-managed `open_ai` / `gpt-4o-mini` in the Standard tier, subject to current availability/pricing and trial credits; omit a custom `think.endpoint`. Do not require `OPENAI_API_KEY` or a bring-your-own OpenAI endpoint. The server uses `DEEPGRAM_API_KEY` with Member-level permissions or higher to call `POST https://api.deepgram.com/v1/auth/grant`. Retain the existing internal `{ clientSecret, expiresAt }` normalization (ISO UTC expiry); here `clientSecret` contains the temporary Deepgram bearer token, not an OpenAI credential. Keep token handling inside A's adapter and never expose permanent keys, raw provider payloads, or credential logs.
3. Implement `POST /api/realtime/token` with body `{ sessionId }`. Call C's `requireUser` and `requireOwnedSession` before issuance; absent auth integration/configuration returns 503, anonymous requests 401, foreign sessions 404. Return `no-store`; validate same-origin POSTs and enforce the agreed per-user request limit. A simple in-process limiter is only a local aid; keep public issuance disabled until deployment-wide abuse controls exist. C coordinates deployment controls; A owns route enforcement.
4. For independent manual development before C lands, use a minimal development-only voice harness, separate from B's `/study`, bound to loopback. A Node-only issuer or strictly local development route may supply the temporary token. Before enabling it, audit guards so production and preview deployments cannot serve the harness or issue billable credentials, even without C's auth. Do not add a deployed auth-bypass flag. Committed harness code must remain development-only; credentials and local artifacts stay untracked. Automated tests inject a fake issuer. The default token TTL is 30 seconds; mint on explicit connect and use immediately, not from a stored permanent browser key.
5. Implement explicit start, microphone permission, listening/speaking indicators, natural speech barge-in, and explicit interruption. Wire current SDK user-speech events to immediate playback interruption so students can continue speaking. Release tracks, playback/audio contexts, SDK/WebSocket connections, timers, and listeners on stop, failure, unmount, and retry. Keep one active connection and bound reconnection behavior so retries cannot reopen a stopped session or repeatedly mint billable credentials.
6. Add concise Socratic Algebra I/distributive-property instructions: introduce Newton as a study companion, ask one guiding question, allow thinking time, do not roleplay Isaac Newton, and do not claim to see work or remember history before those inputs exist. Surface denied permission, expired credential, missing configuration, network failure, and disconnect as recoverable errors.

**External requirements:** a Deepgram account with usable trial credits (verify balance/model access), a server-only Member-level-or-higher key, microphone, and a browser supporting the SDK's audio capture/playback and WebSocket connection. Use localhost or HTTPS. No separate OpenAI API key is needed for managed voice. C's auth, owned study session, and abuse controls are required for deployed voice. B is not required for local adapter validation.

**A1 acceptance:** a developer can start a real conversation, capture microphone audio, hear a spoken response, interrupt speech naturally, continue the conversation, stop, and start again. Stop releases the browser microphone indicator and connection resources; stopping while connecting also releases late resources. Unavailable credentials and connection failures show recoverable errors. Failed starts do not leave media open or auto-retry indefinitely. No permanent key appears in client bundles, HTTP responses, or logs. Deployed routes make zero provider calls when auth is missing/unwired; unauthenticated production/preview issuance fails closed. Report local real-voice success separately from deployed integration readiness.

**Tests:** automate state transitions, duplicate starts, stop-while-connecting, interruption, unsubscribe/cleanup, expired credential handling, denied auth/foreign sessions, and issuer failure using mocks. Manually test a real conversation, interruption, denied microphone access, disconnect/reconnect, navigation cleanup, and inspect network responses for short-lived credentials only. Never put live calls in `npm test`.
